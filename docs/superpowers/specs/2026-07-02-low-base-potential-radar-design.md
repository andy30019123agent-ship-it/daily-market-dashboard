# 低基期潛力雷達（Low-Base Potential Radar）設計

日期：2026-07-02
狀態：設計已與 Andy 核可，待寫實作計劃

## 目標

在既有「每日台美股戰略儀表板」中，新增一個能找出「**低基期、但法人正悄悄吸籌、且有未來題材／催化劑正在醞釀**」的台股標的的互動視角。

對準 Andy 的原始問題：「怎樣找到低基期但有在隱隱發酵的未來題材」。核心是「三（四）個條件同時成立」：
1. **低基期**：股價還沒漲、位置低。
2. **法人吸籌**：法人默默買、股價還沒反應。
3. **未來題材**：可歸類到題材／產業。
4. **催化劑（加分）**：有正在醞釀、還沒被市場注意的發酵點。

## 非目標（Out of Scope）

- 不做全市場獨立掃描低基期（那是做法 B：自建歷史股價快取，本次不做，列為未來擴充）。
- 不做主動推播（本功能是互動探索圖表，不推 TG）。
- 不提供買賣建議；所有輸出標註「跡象非保證、研究起點」。
- 不碰美股（FinMind 無美股歷史；本功能限台股）。

## 使用者決策（brainstorming 結論）

- 呈現形式：**互動探索圖表**，放進現有「資金流雷達」區當**新切換模式**（象限視角 ｜ 🌱 低基期潛力）。
- 低基期定義：**組合判斷**（股價在一年區間偏低 + 近半年沒大漲）。
- 題材：**AI 對候選股貼題材標籤**，**產業別當保底**。
- 催化劑：AI 對候選股**上網查潛在發酵點**，寫成一句、標線索非保證。
- 資料策略：**做法 A —— 籌碼先篩，候選才查歷史**（省 FinMind 額度、精準、對準三合一）。

## 架構總覽

沿用現有每日管線（GitHub Actions `daily.yml`，台北 18:36），在既有 `radar` 資料之後，多一段「低基期潛力」漏斗，產出新的 `potential` 區塊寫進當天 `public/data/<date>.json`；前端 `Radar.jsx` 讀取並以新模式呈現。此區塊**獨立**，失敗不影響主戰報推播。

### 資料管線（四關漏斗）

1. **全市場（已有）**：沿用 `build_market_radar` 產出的 `radar.stocks`，每檔含 `code / name / pct(當日漲跌%) / inst_net_yi(法人淨買超億) / value_yi(成交值億) / sector(產業別)`。

2. **吸籌篩選**（純運算，用已有資料）：挑「法人買、股價還沒噴」的候選。
   - 條件：`inst_net_yi ≥ INST_MIN_YI`（近 N 日累積淨買超，預設 1 億）且 `pct` 溫和（`pct ≤ PCT_MAX`，預設 +3%，還沒起漲）。
   - 用**近 N 日累積**（預設近 3~5 日，聚合已存的歷史 `<date>.json` 之 `radar`，與前端 v2 `aggregateRadar` 同思路）讓吸籌訊號更穩，避免單日雜訊。
   - 取吸籌強度 Top `CAND_MAX`（預設約 20~40 檔）進下一關。

3. **低基期篩選**（只對候選查 FinMind 一年日 K）：
   - 端點：`https://api.finmindtrade.com/api/v4/data?dataset=TaiwanStockPrice&data_id=<code>&start_date=<一年前>`，回 `data[]` 含 `date/open/max/min/close`。
   - 指標一 **股價位置** `price_pos = (close - low_1y) / (high_1y - low_1y)`，越低越低基期；門檻 `price_pos ≤ POS_MAX`（預設 0.4）。
   - 指標二 **近半年漲幅** `chg_6m = close / close_6m_ago - 1`；門檻 `chg_6m ≤ CHG6M_MAX`（預設 0.15）。
   - 兩者皆符合 → 留下（約 5~20 檔）。

4. **AI 加值**（只對最終候選，沿用 `gen_soft_openai` 的 `gpt-4o-search-preview`，有網路搜尋）：
   - 對每檔產：`theme`（題材標籤，如「AI 散熱」「機器人」「矽光子」；查不到就用 `sector` 產業別保底）。
   - `catalyst`（🌱 潛在發酵點，一句話，上網查「正在醞釀、還沒被市場注意的催化劑」：即將法說／新產品／政策／轉單／產業拐點）。查不到留空、不硬編。

門檻常數（`INST_MIN_YI / PCT_MAX / N日 / CAND_MAX / POS_MAX / CHG6M_MAX`）集中定義、方便日後調整；預設值上線後依實際結果校正。

### 資料格式（day.json 新增欄位）

```json
"potential": {
  "window_days": 5,
  "stocks": [
    {
      "code": "1234",
      "name": "某某",
      "pct": 0.5,
      "inst_net_yi": 3.2,
      "price_pos": 0.28,
      "chg_6m": 0.06,
      "theme": "AI 散熱",
      "catalyst": "傳 8 月新平台送樣，法人月內轉買",
      "sector": "電子零組件",
      "history": "ok"
    }
  ]
}
```

- `history` 標 `ok / missing`（FinMind 抓不到時標 missing、跳過分類但可留紀錄）。
- schema 驗證相容舊資料（無 `potential` 欄的舊日期正常）。

### 前端（Radar.jsx 新模式）

- 「資金流雷達」區頂部模式切換多一顆「🌱 低基期潛力」（現有：象限視角）。
- **散佈圖**：X = 股價位置（左＝越低基期）、Y = 法人吸籌（越上越多）→ **左上角＝「低基期＋有人偷買」黃金區**，高亮。
- **候選清單卡片**，每檔顯示：股名/代號 ｜ 股價位置% ｜ 近半年漲幅 ｜ 法人吸籌 ｜ 🏷️題材標籤 ｜ 🌱潛在發酵點 ｜ 可點開 K 線（沿用 ChartModal）。
- 角落標「跡象非保證，研究起點」。
- 沿用既有毛玻璃卡片內 modal 要用 `createPortal` 到 body（避免 backdrop-filter 造成 fixed 錯位，已知踩雷）。

## 錯誤處理

- FinMind 抓不到／額度滿 → 該股標 `history:"missing"` 跳過，不讓整條管線掛（沿用專案容錯風格）。必要時加 FinMind token 與呼叫間隔（sleep）避免限流。
- AI 查不到發酵點 → `catalyst` 留空，不硬編。
- 當天無候選 → 前端優雅空狀態「今日無低基期吸籌標的」。
- 本區塊獨立於主戰報：`potential` 產製失敗只影響此模式，**不阻擋主戰報數據與推播**。
